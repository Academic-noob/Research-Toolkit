## 1. 总体计算逻辑

这套脚本的目的不是简单复制文件，而是强制把 nonrad 计算链分清楚：

```text
endpoint relax
    ↓
CCD structure generation
    ↓
CCD static single-point calculations
    ↓
WSWQ overlap calculations
    ↓
PES extraction
    ↓
Wif extraction
    ↓
capture coefficient C(T)
```

对应目录：

```text
nonrad_case/
├── 01_relax/
├── 02_ccd_structures/
├── 03_static/
├── 04_wswq/
└── 05_results/
```

## 2. 默认电荷态定义

`00_setup_nonrad_case.sh` 顶部默认：

```bash
GROUND_CHARGE="charge_state_0"
EXCITED_CHARGE="charge_state_-1"
```

因此默认：

```text
ground  = charge_state_0
excited = charge_state_-1
```

这通常对应空穴俘获：

```text
charge_state_-1 + h+ -> charge_state_0
```

如果你以后计算电子俘获或其他电荷态组合，需要修改这两行。

## 3. 每个电荷态目录需要放什么

以 `charge_state_-1/` 为例：

```text
charge_state_-1/
├── CONTCAR
├── NELECT
├── POTCAR
├── INCAR.relax
├── INCAR.static
├── INCAR.wswq
├── KPOINTS.relax
├── KPOINTS.static
└── KPOINTS.wswq
```

### 3.1 `CONTCAR`

上一步已经优化好的电荷态结构。脚本会把它复制为 endpoint relax 的 `POSCAR`。

例如：

```text
charge_state_-1/CONTCAR -> nonrad_case/01_relax/excited/POSCAR
```

### 3.2 `NELECT`

只写电子数，例如：

```text
384
```

脚本会自动将其写入对应 INCAR。

### 3.3 `POTCAR`

对应体系的 POTCAR。两个电荷态通常原子种类相同，POTCAR 应相同，但仍建议两个目录都放一份，避免路径混乱。

### 3.4 `INCAR.relax`

endpoint 结构优化模板。应包含：

```text
IBRION = 2
NSW > 0
LWAVE = .TRUE.
LCHARG = .TRUE.
```

### 3.5 `INCAR.static`

CCD 每个结构的固定结构单点模板。应包含：

```text
IBRION = -1
NSW = 0
LWAVE = .TRUE.
LCHARG = .TRUE.
```

`LWAVE` 和 `LCHARG` 必须为真，因为 WSWQ 后面需要 `WAVECAR` 和 `CHGCAR`。

### 3.6 `INCAR.wswq`

WSWQ overlap 计算模板。应包含：

```text
ISTART = 1
ICHARG = 11
ALGO = None
LWSWQ = .TRUE.
LWAVE = .FALSE.
LCHARG = .FALSE.
```

WSWQ 阶段只生成 `WSWQ`，不应该再改写 `WAVECAR`。

### 3.7 `KPOINTS.relax`

endpoint relax 使用。可以用单 k 点，例如：

```text
KPOINTS
1
Reciprocal
  0.25000000  0.25000000  0.25000000  1.0
```

### 3.8 `KPOINTS.static`

CCD static 使用。双k点计算量增加1倍，建议单K点即可：

```text
KPOINTS
2
Reciprocal
  0.25000000  0.25000000  0.25000000  1.0
  0.00000000  0.00000000  0.00000000  0.0
```
```text
KPOINTS
1
Reciprocal
  0.25000000  0.25000000  0.25000000  1.0
```
```
KPOINTS
Automatic mesh
0
G
1 1 1
0 0 0
```

### 3.9 `KPOINTS.wswq`

必须和 `KPOINTS.static` 保持一致。

如果 static 用双 k 点，WSWQ 也用双 k 点。  
如果 static 用 single-k，WSWQ 也用 single-k。

## 4. `00_setup_nonrad_case.sh` 的作用

主控脚本。可执行模式：

```bash
bash scripts/00_setup_nonrad_case.sh relax
bash scripts/00_setup_nonrad_case.sh ccd
bash scripts/00_setup_nonrad_case.sh static
bash scripts/00_setup_nonrad_case.sh wswq
bash scripts/00_setup_nonrad_case.sh all_after_relax
```

### 4.1 `relax`

生成 endpoint relax 输入：

```bash
bash scripts/00_setup_nonrad_case.sh relax
```

输出：

```text
nonrad_case/01_relax/ground/
nonrad_case/01_relax/excited/
```

复制逻辑：

```text
charge_state_0/CONTCAR      -> 01_relax/ground/POSCAR
charge_state_-1/CONTCAR     -> 01_relax/excited/POSCAR
charge_state_0/INCAR.relax  -> 01_relax/ground/INCAR
charge_state_-1/INCAR.relax -> 01_relax/excited/INCAR
```

同时自动写入对应 `NELECT`。

### 4.2 `ccd`

用 relax 后的 endpoint CONTCAR 生成 CCD 结构：

```bash
bash scripts/00_setup_nonrad_case.sh ccd
```

要求这两个文件存在：

```text
nonrad_case/01_relax/ground/CONTCAR
nonrad_case/01_relax/excited/CONTCAR
```

输出：

```text
nonrad_case/02_ccd_structures/ground/0..8/POSCAR
nonrad_case/02_ccd_structures/excited/0..8/POSCAR
nonrad_case/02_ccd_structures/ccd_points.tsv
nonrad_case/02_ccd_structures/ccd_summary.txt
```

### 4.3 `static`

准备 CCD static 单点输入：

```bash
bash scripts/00_setup_nonrad_case.sh static
```

输出：

```text
nonrad_case/03_static/ground/0..8/
nonrad_case/03_static/excited/0..8/
```

每个目录包括：

```text
POSCAR
INCAR
KPOINTS
POTCAR
```

### 4.4 `wswq`

准备 WSWQ 输入：

```bash
bash scripts/00_setup_nonrad_case.sh wswq
```

要求 static 已经完成，并有：

```text
nonrad_case/03_static/<branch>/<i>/WAVECAR
nonrad_case/03_static/<branch>/<i>/CHGCAR
nonrad_case/03_static/<branch>/<i>/vasprun.xml
```

输出：

```text
nonrad_case/04_wswq/ground/0..8/
nonrad_case/04_wswq/excited/0..8/
```

WSWQ 文件复制逻辑：

```text
03_static/<branch>/4/WAVECAR   -> 04_wswq/<branch>/<i>/WAVECAR
03_static/<branch>/<i>/WAVECAR -> 04_wswq/<branch>/<i>/WAVECAR.qqq
03_static/<branch>/4/CHGCAR    -> 04_wswq/<branch>/<i>/CHGCAR
03_static/<branch>/4/POSCAR    -> 04_wswq/<branch>/<i>/POSCAR
```

`4` 是默认参考点，即 9 点中的 Q=0。

## 10.1 可选修正：Sommerfeld 因子与 charged-supercell scaling

这一部分对应新增脚本：

```text
scripts/06_scaling_corrections.py
```

它用于计算两个官方 workflow 中常见的可选修正：

```text
1. Sommerfeld factor：长程库仑吸引/排斥修正
2. charged-supercell scaling：带电超胞中 Wif 的有限尺寸缩放修正
```

注意：这个脚本**不会自动改写** `04_calculate_capture.py` 的结果，也不会覆盖原始 `Wif`。  
它只输出修正因子、图和报告。这样可以把基础捕获系数、Sommerfeld 修正、带电超胞修正分开记录，避免结果混乱。

### 10.1.1 Sommerfeld 因子什么时候用

Sommerfeld 因子描述带电缺陷与自由载流子之间的长程库仑相互作用。

如果是吸引相互作用，捕获率会增强；如果是排斥相互作用，捕获率会被抑制。

定义：

```text
Z = q_d / q_c
```

其中：

```text
q_d = 缺陷电荷
q_c = 被捕获载流子的电荷
```

例如，负电缺陷捕获空穴：

```text
q_d = -1
q_c = +1
Z = -1
```

这表示吸引中心，Sommerfeld factor 通常大于 1。

运行示例：

```bash
python scripts/06_scaling_corrections.py \
  --case-root nonrad_case \
  --Z -1 \
  --m-eff 0.18 \
  --eps-static 8.9 \
  --T 300 \
  --tag hole_capture
```

参数含义：

```text
--Z            q_d / q_c
--m-eff        载流子有效质量，空穴俘获用空穴有效质量，电子俘获用电子有效质量
--eps-static   静态介电常数
--T            单点报告温度，默认 300 K
--tag          输出文件标签
```

输出文件：

```text
nonrad_case/05_results/scaling/hole_capture_scaling_report.txt
nonrad_case/05_results/scaling/hole_capture_sommerfeld_vs_T.csv
nonrad_case/05_results/scaling/hole_capture_sommerfeld_vs_T.png
```

如果基础捕获系数是：

```text
C_raw(T)
```

则 Sommerfeld 修正后可以写成：

```text
C_S(T) = f_S(T) × C_raw(T)
```

其中 `f_S(T)` 来自 `sommerfeld_vs_T.csv`。

---

### 10.1.2 charged-supercell scaling 什么时候用

如果电子-声子矩阵元 `Wif` 是在**中性电荷态**下计算的，通常不需要 charged-supercell scaling。

如果你不得不用**带电超胞**计算 `Wif`，缺陷电荷会和离域能带边缘发生长程库仑相互作用，导致缺陷附近的电荷密度被虚假增强或抑制。这时可以用 `charged_supercell_scaling` 估算缩放因子。

运行示例：

```bash
python scripts/06_scaling_corrections_vasp.py \
  --case-root nonrad_case \
  --wavecar nonrad_case/03_static/excited/4/WAVECAR \
  --band-index 191 \
  --def-index 192 \
  --spin 1 \
  --kpoint 1 \
  --tag charged_scaling_excited_190

```

参数含义：

```text
--wavecar      用于缩放分析的 WAVECAR，通常来自带电态 static 目录
--band-index   bulk-like / extended state 的 band index
--def-index    缺陷态 band index
--tag          输出文件标签
```

输出文件：

```text
nonrad_case/05_results/scaling/charged_scaling_ground_189_scaling_report.txt
nonrad_case/05_results/scaling/charged_scaling_ground_189_charged_supercell_scaling.png
```

报告里会包含：

```text
raw_factor_from_charged_supercell_scaling
recommended_Wif_scaling_1_over_factor
```

按照官方示例：

```text
scaling = 1 / factor
```

如果确实需要修正，则：

```text
Wif_corrected = Wif_raw × scaling
```

然后用 `Wif_corrected` 重新运行：

```bash
python scripts/04_calculate_capture.py ...
```

### 10.1.4 推荐记录方式

正式整理结果时，不要只报一个混合后的数。建议分三层记录：

```text
1. 基础捕获系数：
   C_raw(T) = get_C(...)

2. Sommerfeld 修正后：
   C_S(T) = f_S(T) × C_raw(T)

3. 如果 Wif 来自带电超胞并确实需要有限尺寸修正：
   Wif_corrected = Wif_raw × scaling
   再用 Wif_corrected 重新计算 C(T)
```

这样可以清楚说明每个修正来自哪里，也方便以后检查结果是否被重复修正。

---

### 10.1.5 实战判断

对你现在的深能级缺陷流程，优先顺序是：

```text
第一步：先完成基础 nonrad 流程，得到 C_raw(T)
第二步：根据缺陷电荷和载流子类型计算 Sommerfeld factor
第三步：只有当 Wif 是在带电超胞中计算时，才考虑 charged-supercell scaling
```

不要默认所有缺陷都需要 charged-supercell scaling。  
如果 `Wif` 是在中性电荷态下计算的，通常不做这个缩放，只记录“不引入 charged-supercell scaling”。

## 13. 常见错误

### 错误 1：`NELECT: 383`

错误。当前脚本会读成 `NELECT:`。  
必须改成：

```text
383
```

### 错误 2：把目录编号当 Q

错误：

```python
wswqs = [(4, ".../WSWQ")]
```

如果 `4` 是目录编号，它不是 Q。

正确：使用 `ccd_points.tsv` 中的 Q 坐标。

### 错误 3：`initial_vasprun` 指向 WSWQ 目录

```text
03_static/ground/4/vasprun.xml
```

错误。

```text
03_static/ground/i/WAVECAR -> 04_wswq/ground/i/WAVECAR.qqq
```

## 15. 最终硬规则

1. `NELECT` 文件只写数字。
2. `CONTCAR` 是 endpoint 输入。
3. `03_static` 只做固定结构单点。
4. `04_wswq` 只做 WSWQ。
5. `WAVECAR.qqq` 只在 WSWQ 阶段出现。
6. `initial_vasprun` 必须来自 `03_static/<branch>/4/vasprun.xml`。
7. Wif 的 Q 坐标必须来自 `ccd_points.tsv`。
8. `CHGCAR=0` 的 static 目录不能作为 WSWQ 来源。
9. 不要混用旧目录。
10. 每一步完成后跑 `05_audit_nonrad_case.sh`。
